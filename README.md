# МТС Банк — C2C-прототип

Интерактивный прототип мобильного приложения переводов по тестовому заданию. Базовый макет — 402 × 874 px.

## Запуск

Node.js 20+:

```sh
npm start
```

Открыть http://localhost:5173. Зависимости для самого приложения не нужны.

## Реализовано

- Стартовый экран с анимированными руками, картой и сменой сообщений
- Демонстрационный вход по телефону
- Главная с переключаемыми картами, получателями и сворачиваемой историей
- Меню способов перевода
- Авторизованный перевод: выбор и добавление карты, ввод получателя и суммы
- Определение банка по первым восьми цифрам карты через серверный запрос к Binlist; при недоступности — явно обозначенный демонстрационный выбор
- Комиссия, итоговое списание, ошибка нехватки средств и демонстрационное пополнение
- Международный пример RUB → UZS с условным курсом 1 ₽ = 150 UZS и комиссией 0 ₽
- Сохранение получателя при вводе карты, повтор перевода из истории
- Обработка перевода, экран успеха с конфетти и деталями
- Сохранение демонстрационных данных и восстановление страницы в текущей вкладке

Прямая ссылка на гостевую форму: http://localhost:5173/?screen=guest

Предпросмотр успеха без создания операции: http://localhost:5173/?preview=success

## Важно

Это демонстрация: реальных списаний, авторизации и привязки карт нет. Международный курс условный и не является предложением банка. Расчёт российских переводов иллюстрирует тариф 1,5%, минимум 50 ₽ в другой российский банк и 0 ₽ в МТС Банк; условия реального перевода должен подтверждать банк.

Полные номера карт не сохраняются в браузерном хранилище. Для определения банка внешний сервис получает только первые восемь цифр. При добавлении карты баланс остаётся неизвестным.

Гостевой перевод доступен со стартового экрана и по ссылке ?screen=guest. Экран соответствует Figma 138:5534: номер карты отправителя, демонстрационные срок действия и CVC/CVV, номер получателя и сумма с валютой находятся на одном экране. Без клавиатуры CTA находится внизу; при вводе используется системная клавиатура. Сканирование показывает пояснение о ручном вводе. Расчёт комиссии, подтверждение и демонстрационное завершение используют общую форму перевода.

## Демонстрационная проверка доступности карты

Корректность номера (Luhn) и доступность перевода проверяются отдельно. `src/card-availability.js` моделирует ответы: ожидание, доступность и отказ с блокировкой продолжения. Это не банковская проверка — в интерфейсе есть пометка демо. В production необходим API платёжного провайдера; BIN определяет банк, но не подтверждает доступность конкретной карты.

Для проверки отказа: `4000 0000 0000 0002`. Успешный гостевой пример: отправитель `4111 1111 1111 1111`, получатель `5555 5555 5555 4444`. Не вводите реальные карточные данные. При недоступном BIN-сервисе используется явно демонстрационный расчёт для выбранного направления. Гостевой сценарий использует общие расчёт, подтверждение, обработку и успех, без предложения сохранить получателя.

Проверка полного гостевого сценария при запущенном сервере: `node tests/guest-flow.mjs`.

Градиентный фон, оригинальный глобус и индикатор, подпись «Обрабатываем перевод». Индикатор не сообщает вымышленный процент выполнения. Белая дорожка восстановлена стилем: экспорт Figma содержит SVG-прямоугольник нулевой высоты, который браузер не рисует.

Анимация загрузки: глобус равномерно вращается (36 секунд на оборот), розовый индикатор движется по дорожке за 2,5 секунды и возвращается. Движение работает только пока отображается обработка; фактический процент не моделируется. При `prefers-reduced-motion` вращение отключено, индикатор мягко меняет прозрачность. Проверка `tests/loading-figma.mjs` также проверяет движение обеих анимаций и этот режим доступности.

## Выбор валюты суммы

В поле суммы доступны ₽ / $ / €. Для МТС Банка и российских карт по умолчанию выбран рубль; при выборе другой карты валюта возвращается к её значению по умолчанию. Если единицы суммы меняются вместе с картой, прежняя сумма очищается. Ручное переключение валюты сохраняет введённое число.

По заданию используются фиксированные демонстрационные курсы: 1 USD = 82,70 RUB, 1 EUR = 90,98 RUB. Для долларовой/евровой суммы видны демо-курс и рублёвый эквивалент. Комиссия, нехватка средств и итоговое списание рассчитываются в рублях. Пример: 100 $ → 8 270 ₽ + 124,05 ₽ комиссии = 8 394,05 ₽. Подтверждение показывает введённую валюту и пересчёт, операция сохраняет рублёвую сумму и исходные валюту/сумму/курс. Курсы не запрашиваются у банка и не являются текущими рыночными котировками.

Проверки: `npm test` включает конвертацию и округление; `node tests/amount-currency.mjs` при запущенном сервере проверяет выбор, курсы, комиссию, недостаток средств, адаптивность и завершение перевода. Снимки: `screenshots/transfer-currency-*.png`.

## Нижняя кнопка и клавиатура

В форме перевода нижний блок занимает свободное место по высоте и при закрытой клавиатуре располагает CTA внизу, даже если карты и сумма ещё не заполнены. При 402 × 874 кнопка находится на y=751, как в макете. Высота страницы учитывает `visualViewport` и безопасные отступы устройства. Сам по себе фокус на поле в настольном браузере не считается открытой клавиатурой. При коротком экране/длинной форме остаётся обычная прокрутка: кнопка не перекрывает поля и ошибки.

Кнопка «Понятно» в уведомлении о сканировании оформлена как основной CTA: чёрный фон, белый шрифт, 56 px высоты, радиус 20 px, на всю ширину содержимого диалога.

Проверка: `node tests/transfer-footer.mjs` — пустая форма, фокус без клавиатуры, имитация открытия/закрытия клавиатуры через visualViewport, короткие экраны, оформление диалога и закрытие по Enter. Снимки: `screenshots/transfer-empty-footer-402x874.png`, `screenshots/transfer-footer-keyboard-simulation.png`, `screenshots/scan-notice-cta.png`. Физическая экранная клавиатура iOS/Android отдельно не проверялась.

Срок действия и CVC/CVV изначально пустые и не заполняются при наведении. При фокусе пустое поле получает демонстрационное значение (12/30 или 123); уже введённое значение сохраняется. Срок выбирается в барабане (текущий год + 10 лет), CVC/CVV вводится вручную и маскируется. Для демо-карты правильный срок — 12/30; другой срок показывает «Неверный срок действия».

Гостевой экран: проверка состояний всех полей — `node tests/guest-input-states.mjs`. Непустые номера отправителя и получателя очищаются крестиком (включая ошибку); сканер виден только в пустом поле. CVC/CVV имеет состояния пустого поля, фокуса, заполнения и ошибки; код можно показать/скрыть и очистить. Для демо-карты верный код — 123. Все подписи ошибок и рамки используют #FF1524. Фокус срока действия и CVC/CVV — #414141.

При фокусе пустого номера отправителя или получателя гостевого перевода появляется необязательная подсказка «Пример для демо»: 9112 3810 1521 3812 / 2200 7893 3254 1984 (Figma 171:5848). Ручной ввод сохраняется. Только эти точные демо-номера проходят отдельную проверку прототипа, без BIN-запроса; остальные номера проверяются как прежде. Проверка: `node tests/guest-demo-cards.mjs`.
